## 0. Backup — non-negotiable, two of this update's migrations are irreversible

`taxonomy.0005` (the przedmiot merge, which renumbers a few exercises and discards which
university each came from) and `courses.0007` cannot be reversed. The backup IS the rollback.

```bash
BACKUP_TS=$(date +%Y%m%d-%H%M%S)
cd /home/todoonet/todonet
cp backend/db.sqlite3 ~/edmat-db-backup-$BACKUP_TS.sqlite3
tar czf ~/edmat-media-backup-$BACKUP_TS.tar.gz backend/media/
tar czf ~/edmat-logdata-backup-$BACKUP_TS.tar.gz backend/logdata/ 2>/dev/null || true
```

## 1. Sync the payload — never `db.sqlite3`, `media/`, `logdata/`, or `.venv`

The update package deliberately contains none of those, so a plain rsync **without `--delete`**
cannot clobber live data:

```bash
rsync -av --exclude='.venv' /path/to/UPDATE-20260810/backend/  /home/todoonet/todonet/backend/
rsync -av --delete /path/to/UPDATE-20260810/frontend/build/    /home/todoonet/todonet/frontend/build/
rsync -av /path/to/UPDATE-20260810/deploy/                     /home/todoonet/todonet/deploy/
```

(`--delete` on `frontend/build/` ONLY — it's fully generated, and stale hashed chunks from the old
build would otherwise accumulate forever. Never `--delete` on `backend/`.)

## 4. Redis (the new, optional half — recommended on this box)

```bash
sudo apt install -y redis-server
sudo systemctl enable --now redis-server
redis-cli ping    # expect PONG
```

Then add one line to `/etc/apache2/envvars` (below the existing EdMat block):

```bash
export EDMAT_REDIS_URL="redis://127.0.0.1:6379/0"
```

With it set, the auth-throttle counters become shared across both mod_wsgi processes (correct at
any worker count — until now each process kept its own), the anonymous-read response cache becomes
genuinely shared, and notification SSE switches from per-connection DB polling to pub/sub push
with a 2-streams-per-account cap. Without it, everything keeps the file-cache/polling behavior —
so if Redis ever misbehaves, deleting that one line and restarting Apache is the full rollback.

Optional standing cache warmth (the TTL is 60 s, so warm at that cadence):

```bash
crontab -e    # add:
* * * * * cd /home/todoonet/todonet/backend && .venv/bin/python3 manage.py preload_cache >> /tmp/edmat-preload.log 2>&1
```

## 5. Apache vhost — this also applies the Aug-5 hardening that never went live

The running `edmat.conf` predates the security-header block (verified during the rescue: the live
site returns none of the headers, including the `/media/` `Content-Disposition: attachment` rule
that keeps user uploads from rendering in-browser). The repo copy has all of it:

```bash
sudo cp /home/todoonet/todonet/deploy/apache/edmat.conf /etc/apache2/sites-available/edmat.conf
sudo apache2ctl configtest        # expect Syntax OK; "Invalid command 'Header'" means: sudo a2enmod headers
sudo systemctl restart apache2    # restart, not reload — new code + new env vars
```

## 6. Smoke test — note the URLS CHANGED with the taxonomy rename

```bash
curl -I  https://edmat.net/                                        # expect 200
curl -s  https://edmat.net/api/disciplines/ | head -c 200          # the NEW taxonomy root — real JSON
curl -s -o /dev/null -w '%{http_code}\n' https://edmat.net/api/fields/   # the OLD root — 404 is CORRECT now
curl -s  https://edmat.net/api/feature-flags/ | python3 -m json.tool     # expect 7 flags; all true except material_uploads_verified_only (inverted semantics, seeded false)
curl -I  https://edmat.net/events                                  # new route — expect 200
curl -I  https://edmat.net/bookings                                # new route — expect 200
```

Then the authenticated check (anonymous curls can't catch a broken `WSGIPassAuthorization`):

```bash
TOKEN=$(curl -s -X POST https://edmat.net/api/auth/login/ -H 'Content-Type: application/json' \
    -d '{"email":"YOUR_EMAIL","password":"YOUR_PASSWORD"}' \
    | python3 -c "import sys,json;print(json.load(sys.stdin).get('token',''))")
curl -s -o /dev/null -w "authenticated me -> %{http_code}\n" \
    https://edmat.net/api/auth/me/ -H "Authorization: Token $TOKEN"    # expect 200
```

And with Redis on, confirm it's actually being used:

```bash
curl -s -D- -o /dev/null https://edmat.net/api/disciplines/ | grep -i x-edmat-cache   # miss
curl -s -D- -o /dev/null https://edmat.net/api/disciplines/ | grep -i x-edmat-cache   # stored
curl -s -D- -o /dev/null https://edmat.net/api/disciplines/ | grep -i x-edmat-cache   # hit
```

Finally, in a real browser: log in with a real account, open a course page, the new Events tab on
the homepage, and confirm the navbar's "Add…" / account menus render.
