## What is in it

- **Six ways into a comment, and a chemistry editor behind one of them** (root CLAUDE.md §17AV).
  A new `chem` app: `ChemDrawing` stores a Ketcher drawing's own source (KET/MOL/RXN) plus a
  rebuilt-from-an-allowlist SVG (or a re-encoded WebP), and content embeds it as an ordinary
  site-media `<img data-chem=…>`. New endpoints `GET/POST/PUT /api/chem-drawings/…`, a new
  `chem_drawing` throttle scope (60/hour), and a new **`chemistry` feature flag, seeded ON** —
  turning it off removes the button and refuses the API while drawings already in content keep
  rendering. The other five input kinds (Markdown file, LaTeX with a live preview, JSON, PDF,
  picture) are frontend-only, over the attachment and editor machinery that already existed.
  ChemDoodle was vendored and removed the same day — GPL, and this project is MIT.
- **DSA Article 16 notice-and-action** (§17AW). A new `legal` app: `LegalNotice` is a report that a
  *specific published piece of content is illegal*, filable by anyone including guests (contact
  email required, `reporter` may be NULL — truly anonymous), with a mandatory statement of reasons
  when staff decide it. Deliberately **not** behind any `FeatureFlag`: a legal notice channel must
  not go dark because somebody quieted the issue tracker. New endpoints under
  `/api/legal-notices/`, a new `legal_notice` throttle scope (10/hour), a staff queue at
  `/legal/queue`, a filing form at `/legal/notice`, a point-of-contact page at `/legal` (linked
  from the footer, ungated). Acting on a notice reuses `moderation.services.resolve_report_decision`
  — the same function a routine community report already runs — so content mutation and the
  Art. 17 notification to the content's author take no second code path.
- **A real sanitizer bug fixed in passing**: bleach never falls through to its `'*'` attribute rule
  for a tag that has its own attribute callable, so every `<img class=…>` had been losing its
  `class` on write. Comment bodies are now sanitized on write at all (previously only the
  frontend's DOMPurify pass stood between a `<script>` and the next reader) and rendered through
  the sanitized Markdown+KaTeX pipeline.

## Server-side steps beyond the normal Part-A sync

**None.** No new pip package (`chem` needs only Pillow and the in-repo `imaging` module, both
already there; `legal` needs nothing outside Django/DRF), no new environment variable, no vhost
change. `import_legacy_corpus` and `seed_demo_users` are not run, as always.

Two things worth knowing about, neither of them a step:

- **The Ketcher bundle is a 21 MB JavaScript chunk** (the Indigo WASM is base64-inlined into it,
  so there is no separate `.wasm` asset and therefore no `application/wasm` MIME question for
  Apache). It is **lazily imported** — a reader who never opens the chemistry dialog never fetches
  it, and it is absent from the entry HTML's modulepreloads. The tarball grew to ~12 MB because of
  it.
- **Worth checking once, not fixed here:** the vhost compresses
  `application/javascript`/`application/x-javascript`, but modern Debian/Ubuntu `mime.types` maps
  `.js` to `text/javascript`, which that list does not cover — in which case that 21 MB chunk is
  served uncompressed. One command on the server answers it:
  ```bash
  curl -sI -H 'Accept-Encoding: gzip' https://edmat.net/_app/immutable/chunks/<any>.js | grep -i 'content-type\|content-encoding'
  ```
  If there is no `Content-Encoding: gzip`, adding `text/javascript` to the
  `AddOutputFilterByType DEFLATE` line in `deploy/apache/edmat.conf` (and installing it — see
  `apply-on-server.sh` step 4b) fixes it for every chunk on the site, not just this one. Left out
  of this bundle deliberately so the deploy needs no `/etc/apache2` edit.
