## What is in it

- **Six ways into a comment, and a chemistry editor behind one of them** (root `HISTORY.md` §17AV).
  A new `chem` app: `ChemDrawing` stores a Ketcher drawing's own source (KET/MOL/RXN) plus a
  rebuilt-from-an-allowlist SVG (or a re-encoded WebP), and content embeds it as an ordinary
  site-media `<img data-chem=…>`. New endpoints `GET/POST/PUT /api/chem-drawings/…`, a new
  `chem_drawing` throttle scope (60/hour), and a new **`chemistry` feature flag, seeded ON** —
  turning it off removes the button and refuses the API while drawings already in content keep
  rendering. The other five input kinds (Markdown file, LaTeX with a live preview, JSON, PDF,
  picture) are frontend-only, over the attachment and editor machinery that already existed.
  ChemDoodle was vendored and removed the same day — GPL, and this project is MIT.
- **DSA Article 16 notice-and-action** (§17AW). A new `legal` app: `LegalNotice` is a report that a
  *specific published piece of content is illegal*, filable by anyone including guests (contact
  email required, `reporter` may be NULL — truly anonymous), with a mandatory statement of reasons
  when staff decide it. Deliberately **not** behind any `FeatureFlag`: a legal notice channel must
  not go dark because somebody quieted the issue tracker. New endpoints under
  `/api/legal-notices/`, a new `legal_notice` throttle scope (10/hour), a staff queue at
  `/legal/queue`, a filing form at `/legal/notice`, a point-of-contact page at `/legal` (linked
  from the footer, ungated). Acting on a notice reuses `moderation.services.resolve_report_decision`
  — the same function a routine community report already runs — so content mutation and the
  Art. 17 notification to the content's author take no second code path.
- **A real sanitizer bug fixed in passing**: bleach never falls through to its `'*'` attribute rule
  for a tag that has its own attribute callable, so every `<img class=…>` had been losing its
  `class` on write. Comment bodies are now sanitized on write at all (previously only the
  frontend's DOMPurify pass stood between a `<script>` and the next reader) and rendered through
  the sanitized Markdown+KaTeX pipeline.

## Server-side steps beyond the normal Part-A sync

**None.** No new pip package (`chem` needs only Pillow and the in-repo `imaging` module, both
already there; `legal` needs nothing outside Django/DRF), no new environment variable, no vhost
change. `import_legacy_corpus` and `seed_demo_users` are not run, as always.

Two things worth knowing about, neither of them a step:

- **The Ketcher bundle is a 21 MB JavaScript chunk** (the Indigo WASM is base64-inlined into it,
  so there is no separate `.wasm` asset and therefore no `application/wasm` MIME question for
  Apache). It is **lazily imported** — a reader who never opens the chemistry dialog never fetches
  it, and it is absent from the entry HTML's modulepreloads. The tarball grew to ~12 MB because of
  it.
- **Measured after the bundle went live, and fixed in the vhost: no JavaScript on this site was
  ever being compressed.** The `AddOutputFilterByType DEFLATE` list covered
  `application/javascript`/`application/x-javascript`, but RFC 9239 made `text/javascript` the
  registered type and Debian's `media-types` follows it, so both `.js` and `.mjs` are served as
  `text/javascript` here — a type neither that line nor Ubuntu's stock `deflate.conf` matched.
  Measured on the live site: the Ketcher chunk came down as **21,176,639 bytes with no
  `Content-Encoding` at all** (it gzips to 6.9 MB) and the PDF worker's `.mjs` as 1.26 MB the same
  way, while the HTML, CSS and API JSON beside them were all correctly gzipped — which is why this
  hid for as long as it did. `deploy/apache/edmat.conf` now lists `text/javascript` first,
  keeping the two `application/*` spellings for an older `mime.types`.

  **This needs installing separately — the bundle above was already applied and carries the old
  vhost**, and `apply-on-server.sh` never writes into `/etc/apache2` by design.

  > **If another bundle is going out, use `UPDATE-2026-09-19.md` instead of the scp below.** That
  > bundle's own rsync of `deploy/` puts the fixed vhost on the server for you, and step 4b then
  > prints the install commands. The scp here is only for a server with no bundle in flight.

  From the host machine:

  ```bash
  # $FUW_JUMP is the jump host, login included — deploy/fuw/transfer.sh holds the real value
  # (that file is deliberately untracked); export it here or edit the command.
  scp -o ProxyJump="$FUW_JUMP" \
      deploy/apache/edmat.conf todoonet@webek4.fuw.edu.pl:~/edmat.conf.new
  ```

  Then on webek4, as `todoonet` — the diff is the gate, not decoration: it should show the one
  directive line and its comment and nothing else. Anything more means the installed vhost has
  site-specific edits that must be carried over by hand.

  ```bash
  diff ~/edmat.conf.new /etc/apache2/sites-available/edmat.conf
  sudo cp /etc/apache2/sites-available/edmat.conf ~/edmat.conf.bak-$(date +%Y%m%d-%H%M%S)
  sudo cp ~/edmat.conf.new /etc/apache2/sites-available/edmat.conf
  cp     ~/edmat.conf.new /home/todoonet/todonet/deploy/apache/edmat.conf   # keeps step 4b quiet next time
  sudo apache2ctl configtest && sudo systemctl restart apache2
  # a real asset name, taken from the page — a glob in a URL is not expanded by the server
  JS=$(curl -s https://edmat.net/ | grep -o '/_app/immutable/[^"]*\.js' | head -1)
  curl -sI -H 'Accept-Encoding: gzip' "https://edmat.net$JS" | grep -i 'content-encoding'
  # expect: Content-Encoding: gzip
  ```

  Copying it into `~/todonet/deploy/apache/` as well matters only so the next bundle's vhost-drift
  check compares like with like; the next bundle packed from this repo will carry the fixed file
  anyway.
