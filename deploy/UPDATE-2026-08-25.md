# EdMat — the 2026-08-25 update for webek4.fuw.edu.pl / edmat.net

**Scope: a routine, additive update** — the Part A sync of `DEPLOYMENT.md`, fully automated by
`deploy/fuw/*.sh`. Nothing here renames, merges or drops data; every migration only ADDS tables
and one nullable-with-default column. No new environment variables, no new Python packages, no
Apache change (the new prerendered pages are served by the vhost's existing generic `$1.html`
rewrite). The 2026-08-10 note remains the reference for the breaking-upgrade shape; this one is
what a normal release should look like.

## What is in it

- **Material claims split** (`materials.0015`): `MaterialCoverage.kind` = `covers` | `requires`,
  plus a separate importance vote (`MaterialCoverageImportanceVote`). Existing rows all become
  `covers`; nothing visible changes for them except the popover no longer prints one number under
  two labels. Requirements are structured claims now (the free-text `MaterialRequirement` API stays,
  UI-less; the server had zero rows).
- **Comment up/down votes** (`community.0005`, `CommentVote`) — a ▲ score ▼ column on every thread.
- **The same claims on courses** (`courses.0018`) **and exercises** (`exercises.0008`).
- **Login returns to the page it was clicked on.**
- **Navbar**: "Disciplines" reads "Exercises" / "Zadania"; its collapsed icon is a worksheet.
- **"Other…"** in the discipline/branch pickers of `/submit` and `/submit-material`: names a new
  node inline and creates it (pending) on submit.
- **First paint**: seven hub routes prerendered; `200.html` paints a boot shell from the HTML.
  Measured on a throttled link: `/materials/1` FCP 5.3 s → 1.45 s.

Root `CLAUDE.md` §17AD–§17AE has the reasoning; `test.md` lists the new e2e scripts.

One thing the packaging dry run caught before you did: with the production `PUBLIC_API_BASE_URL=/api`
the prerender of `/submit` and `/submit-material` crashed (a top-level service call runs at build
time, where a relative `/api/…` URL cannot be fetched). Fixed by moving those loads into `onMount`;
`pack.sh` now refuses any build that lacks a prerendered page.

## Steps

Exactly the table in `deploy/fuw/README.md`:

1. **Commit first.** `pack.sh` warns if tracked changes are uncommitted and packs them anyway —
   a bundle that does not match a commit is the one you cannot reproduce later.
2. On this VM: `bash deploy/fuw/pack.sh` → `FUW/UPDATE-20260825.tar.gz`. It now refuses a build
   that lacks the prerendered pages or the boot shell. (Its `npm run build` runs `svelte-kit
   sync`, which leaves a running dev server in a state where the next navigation fails — restart
   `npm run dev` afterwards if you keep reviewing locally.)
3. On the host: `bash deploy/fuw/transfer.sh FUW/UPDATE-20260825.tar.gz`.
4. On webek4 as `todoonet`: `tar xzf UPDATE-20260825.tar.gz && bash UPDATE-20260825/deploy/fuw/apply-on-server.sh`.
   It backs up, rsyncs, `pip install`s (no-op), migrates, fixes permissions, restarts Apache and
   runs the smoke test.
5. Authenticated smoke: `EDMAT_EMAIL=… EDMAT_PASSWORD=… bash UPDATE-20260825/deploy/fuw/smoke.sh`.

## What `smoke.sh` now proves for this release

`/materials` served prerendered (site header in the raw HTML); the SPA fallback carrying the boot
shell; a material claim exposing `kind` + `importance_summary`; `/api/courses/{id}/claims/` and
`/api/exercises/{id}/claims/` answering 200; a comment carrying `score`. Any FAIL there means a
migration or the frontend build did not land — the old code is restorable from the step-0 backup.

## In-browser pass after the restart

- `/materials/<id>` → click a "Covers" claim: one level line, an accuracy vote, an importance vote,
  a thread whose comments have ▲ score ▼. "+ Add requirement" opens the same form with a typed
  1–100 box.
- A course page and an exercise page show "What it covers" / "What's required".
- Open `/exercises/<id>` in a private window: the "∫ EdMat" bar appears before the page fills in.
- Click "Log in" from a deep page: after signing in you are back on that page.
- Narrow the window below 900 px: the first nav icon is a worksheet, not a compass.

## Rollback

Step-0 backups in `~` on webek4 (`edmat-db-backup-<ts>.sqlite3` + media/logdata tarballs), or
`manage.py migrate materials 0014 && migrate community 0004 && migrate courses 0017 && migrate
exercises 0007` followed by re-rsyncing the previous bundle's `frontend/build/`.
