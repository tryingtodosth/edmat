# EdMat — the 2026-08-26 update for webek4.fuw.edu.pl / edmat.net

**Scope: a routine, additive update**, the same shape as 2026-08-25 — fully automated by
`deploy/fuw/*.sh`. No new environment variables, no new Python packages, no Apache change.
**One new Django app (`issues`)** — it arrives in the ordinary backend rsync and is already in
`INSTALLED_APPS`; nothing to enable by hand.

**If the 2026-08-25 bundle was never applied, this one contains it too** (it is packed from
`main`, which includes it): apply this one only, and read `UPDATE-2026-08-25.md` for what that
half changes. All migrations are additive and idempotent, so nothing depends on which of the two
was applied first.

## What is in it

- **"Report issue / Zgłoś błąd"** — a small link under the ∫ EdMat wordmark (drawn over the bar,
  the header does not grow), also in the account menu, the phone drawer and the footer. A modal
  pre-filled with where the person was (page path/title, locale, viewport, browser — all shown,
  path/title editable), four kinds (bug / wrong content / idea / other), a *truly* anonymous
  option (nothing identifying stored), and the reporter's own "may this be published" choice.
  Published reports get `/issues` (list, status filter) and `/issues/{id}` with the shared threaded
  discussion; unpublished ones are staff-only. Staff move a report's status from a panel on its
  page, with a note; a status change notifies a named reporter. **Kill switch: `issues`**, seeded
  ON by `moderation.0022` — `/moderation` → Feature flags to turn it off, which removes every link.
- **Profile counters** — a profile with more than 50 exercises used to say 50 (the tile counted a
  50-row feed slice). Two stored integers each for exercises and materials, recounted on every
  save/delete and **backfilled by the migrations**; the owner sees "+ N unpublished" on their
  Exercises tile, opening an owner-only list.

Root `CLAUDE.md` §17AF–§17AG has the reasoning; `test.md` lists the two new e2e scripts.

## Migrations — all additive, all reversible

| Migration | Adds |
|---|---|
| `accounts.0018`, `accounts.0019` | four `PositiveIntegerField(default=0)` counters on `Profile`, backfilled from the live tables |
| `issues.0001` | the `Issue` table |
| `moderation.0022` | the `issues` key in `FeatureFlag.key` choices, seeds the row on |
| `notifications.0010` | nullable `Notification.issue` FK, the `issue_status_changed` type |

The backfills read `exercises_exercise` / `materials_material` once each; on this corpus that is
milliseconds. Rollback is `migrate <app> <previous>`; the step-0 backup is still taken.

## `UPDATE-20260826-b` — a same-day follow-up (frontend only)

Applied after the first bundle, in answer to a PageSpeed run against the live site:

- **The "Report issue" modal is loaded on demand** rather than imported by the root layout, so its
  chunk leaves every page's boot. (Its ~3.7 KB of CSS is still inlined — SvelteKit 2.70 collects
  stylesheets for dynamic imports too — which is a small share of the ~49 KB layout sheet; **38 KB
  of that sheet is KaTeX's CSS and `@font-face` rules, kept in the layout on purpose so prerendered
  math never paints unstyled** (§17AE). That is what PageSpeed reports as "unused CSS" on pages
  with little math; it is a known trade, not a regression of this release.)
- **The link under the logo moved 17px right**, to sit under the "EdMat" wordmark rather than the ∫.
- No backend change, no migration. Apply exactly like the first bundle; `apply-on-server.sh`'s
  migrate step is a no-op.

Not chased: the 64 ms "forced reflow" attributed to the layout node and the two ~90 ms tasks in
the runtime chunk — neither is new to this release, and no component in the layout tree reads
geometry at load (only `Popover`, on open). Same status as §17AE's note on script evaluation.
