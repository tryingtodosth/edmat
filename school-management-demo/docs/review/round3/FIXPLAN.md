carry on. Re-read a shared file (`admin.js`, `screens/admin.js`, `00-base.js`, `homeroom.js`) before every
edit and apply exact-string edits only. Keep `node --test tests/` green (437 today; only up; 0 todo),
`node scripts/checklist-status.js` at 145/145, and run `npm run smoke` once at the end if you touched
`public/`. Until F6 lands, a `fetch failed` in `44-setup` under load is the known harness race: re-run
the file alone before blaming your change. Never `new Date()` in school logic; every notification through
`D.notify`; every delete audited; no new npm dependency; do not reformat files.

## Decisions taken for the agents

- **Erasure vs retention (F3).** Art. 17 erasure anonymises identity fields in classes B50 and A and deletes
  nothing in them; it deletes only in classes marked `operational` and `dziennik-lekcyjny` rows older than
  their retention; art. 9 collections are anonymised, not skipped. The audit log is never touched by
  erasure; the erasure protocol itself is the audit row.
- **Four eyes (F3).** Approving a retention proposal requires a different account from the one that
  created it; `run` requires the approver's confirmation token from the approve response.
- **Signed means digest-matched (F4).** A package is `signed` only when the uploaded signature's digest
  matches; anything else is `stored-unverified` and does not silence the § 22 reminder unless the principal
  explicitly records "accepted without verification" with a reason, which is audited.
- **Blobs on disk (F4).** `data/school/files/<collection>/<id>/…`, one gate `server/lib/blobs.js`
  (write, read, delete, list, sha256), backup includes the directory, deletion follows the row.
- **Groups from the file (F5).** An imported split (`groupLabel`) becomes a real `groups` row per class
  when the admin accepts it in the mapping step; attendance rosters then follow the group.
- **Public route (F2).** `GET /api/compliance/accessibility` stays public but serves a cached rendering
  regenerated when the store version changes, never `facts`, never role logins, and is rate-limited like
  the login route.
