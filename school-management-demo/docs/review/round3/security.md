# Przegląd bezpieczeństwa — runda 3

Adversarial review of the surfaces added in the last working day of `prototype/`, carried out with the
team's authorisation against the working tree. The system holds special-category data of minors, so the
yardstick is GDPR Art. 5(1)(f), Art. 9, Art. 25 and Art. 32 — not "does the feature work".

**Scope.** `server/lib/archive.js` + the archive section of `server/routes/principal.js`;
`server/routes/compliance.js` + `server/lib/compliance.js`; `server/routes/registry.js`;
`server/routes/student.js` § parent-access; `server/routes/messages.js`; `server/routes/retention.js`;
`server/routes/notifications.js` + `public/sw.js`; the import sections of `server/routes/admin.js` with
`server/lib/{import-asc,import-optivum,textdecode,csv,xmlcheck,identity}.js`; `server/lib/domain.js`
(`visibleStudentIds`, `adultAccessState`, `guardianScope`); `server/index.js` (`publicConfig`, the setup
gate, the request log). `server/routes/privacy.js` and `server/routes/meetings.js` were pulled in because
two questions in the brief ("is category A untouchable through **every** path", "what else in `config`
should not go to pupils") lead there.

**Method.** Source review plus exploit scripts driven through the real HTTP stack with
`startServer()` from `tests/helpers.js`. Every finding below was reproduced on a running server; the
scripts are in [`repro/`](repro/) (`node docs/review/round3/repro/s3-NN-*.js`). S-01…S-19 from
[`../security.md`](../security.md) are closed and were not re-tested except where a new surface reopens
them.

## Not exploitable — checked, do not re-test

Everything the brief asked about that came back clean, with the evidence, so the fix round does not
spend time on it.

**Parsers (`import-asc.js`, `import-optivum.js`, `textdecode.js`, `csv.js`, `xmlcheck.js`)**

- **Billion laughs / entity expansion — not possible.** The tokenizer skips `<!DOCTYPE …>` including its
  internal subset (`import-asc.js:42-46`) and never builds an entity table; `unescapeXml` knows five
  fixed names plus numeric references. A classic nested-entity bomb comes through as the literal string
  `&c;` — verified, `repro/s3-07-xml-parsers.js` line 1 (`class name length = 3`). No XXE either: nothing
  in the file resolves an external identifier, and no parser touches the filesystem or the network.
- **Deep nesting in the aSc tokenizer — safe.** `tokenize()` is a flat loop with no stack and no
  recursion; 400 000 elements parse in 1.4 s with no depth effect. (The Optivum *tree* builder is the one
  that recurses — that is S3-19.)
- **Invalid UTF-8 / cp1250 bytes — handled correctly.** Raw `0xB3 0xF1 0x9C 0xFF 0x81` inside an aSc
  attribute decodes through the cp1250 fallback to `łńś˙` + U+FFFD with no crash and no silent loss;
  unassigned code points become U+FFFD rather than disappearing (`textdecode.js:38`).
- **Path-like keys in the Optivum `files` map — not a traversal.** `parseOptivum` (`import-optivum.js:210-230`)
  only ever uses a key as a string: `split('/')`, two regexes and a warning. No `fs` call anywhere in the
  module. `../../etc/passwd` is just a map key.
- **Prototype pollution through CSV headers — no.** `csv.js:76` assigns `r[h] = <string>`; `r.__proto__ = "x"`
  with a string value is a no-op on an object literal, and `column()` reads `Object.keys` only.
- **`xmlcheck.wellFormed` — bounded.** `fail()` stops recording at 50 errors and only then computes the
  line/column (`at()` is inside the guard), and the scanner has an explicit `if (i <= lt) break` forward
  safety. No quadratic path found.

**Archive and ZIP (`lib/archive.js`)**

- **ZIP entry-name injection — closed.** Entry names derive from `yearSlug()` → `safeFileName()`, which
  NFKD-normalises, strips everything outside `[A-Za-z0-9._-]`, removes leading dots and dashes and cuts at
  120 chars. A `year` of `../../etc/passwd\0x` produces `dziennik-etc-passwd-x.xml`, and the archive is a
  well-formed 5-entry ZIP (`repro/s3-22-misc.js`). The `/package` download name goes through the same
  helper. (`year` still needs sanitising for `Content-Disposition` — that is S3-09, a different path.)
- **ZIP64 / entry-count limits — correctly guarded** (`archive.js:76`, `:97`), and the package always has
  exactly five entries, so neither guard is reachable.
- **Package reproducibility — holds.** `packageOf()` rebuilds from the stored `xml`/`html`/`manifestJson`/
  `sealJson` and the stored timestamp, so the SHA-256 of a package downloaded later matches the one
  recorded at generation.

**Compliance**

- **The role gate on the other two documents is intact.** `/api/compliance`, `/api/compliance/facts`,
  `/api/compliance/dpia` and `/api/compliance/dpa` are `['dpo','admin','principal']` and answer 403/503 to
  anonymous and to a pupil, before and after setup (`repro/s3-03-before-setup.js`). Only the
  `accessibility` route is public, and only `facts=1` leaks through it (S3-01).
- **Cache headers on the public route are right**: `Cache-Control: no-store` on every `__raw` response,
  plus the standard CSP/`nosniff`/`frame-ancestors 'none'` set centrally.
- **The role matrix does not name a pupil.** `pupilRef()` reduces the probe subject to `{classId, rollNo}`,
  as intended.

**Notifications and the service worker**

- **`GET /api/notifications/:id/render` has no IDOR.** A foreign id is 403, a missing id 404 —
  reproduced both ways (`repro/s3-18b-render.js`). The 403/404 split is an enumeration oracle in theory
  (and shows a 4.2 ms vs 2.1 ms timing difference), but ids are 12 random hex characters from
  `util.id()`, so there is nothing to enumerate; the team's comment already weighs this trade-off.
- **`noTouch` works as documented.** A `/render` at 03:00 leaves `sessions[].lastActivity` byte-identical,
  while an ordinary GET updates it — measured. The 15-minute inactivity window is not extended by a push.
- **`sw.js` fetch-on-receipt is same-origin and safe.** The URL is built against
  `self.registration.scope` with `encodeURIComponent(id)`; `d.link` must start with `/` and is only ever
  used after `'#'`, so it cannot become an off-origin navigation. Service-worker-initiated fetches are
  not intercepted by its own `fetch` handler, so the rendered wording is never written to Cache Storage.
- **`PUSH_FALLBACK` vs `PUSH_TITLES`** — the fallback table is used only when the school cannot be
  reached, and it is generic; nothing pupil-specific lives in `sw.js`.

**Registry, guardians, messaging**

- **`formal: true` cannot be forged.** Verified from `teacher`, `registrar` and `principal`, with both
  `{"formal":true}` and `{"kind":"decision"}`: everything but the principal is `403 formal_requires_principal`
  (`repro/s3-17-consent-and-formal.js`). The other insert paths (`D.sendMessage`, `domain.js:381`) never
  set `formal`, and the views read the stored flag rather than re-deriving it from `kind`, so a forged
  `kind` does not become a formal notice.
- **A guardian cannot record the adult pupil's consent** (403), and neither can a teacher. Only
  registrar/admin/principal can — that is S3-17, a deliberate design decision, not a hole.
- **`/api/registry/sio/validate` and `/sio/package` are clean.** Errors and warnings identify a pupil by
  register number and `studentId`, never by PESEL; the anonymised package really contains no PESEL and no
  surname (`repro/s3-21-sio.js`).
- **`assertMayReadPupilRecord` holds for the learning record** even when the timetable has been poisoned:
  a librarian, nurse or DPO mapped in as a "teacher" still gets 403 on grades, because the gate tests
  `role === 'teacher'` and not timetable membership.

**Retention**

- **Category A and the pupil register are excluded from every proposal.** `proposableRows()` filters on
  `neverDeletes`, and a live proposal reports `neverDeleted: ["ksiega-uczniow/B50","protokoly-rady-pedagogicznej/A"]`
  (`repro/s3-12-retention.js`). (The erasure route is the hole — S3-06.)
- **A proposal cannot be replayed.** A second `run` with the same `proposalId` is `409 proposal_executed`;
  a second `approve` is `409 proposal_approved`; running an unapproved proposal is `403 approval_required`.
- **The class table cannot be rewritten over the API.** `PATCH /api/admin/retention` accepts only
  `logRetentionYears` and `gradesArchiveRetentionYears`, both with statutory floors; a body carrying a
  hand-made `classes` array is silently ignored and `config.retention` keeps `protokoly-rady-pedagogicznej`
  at category A. `blank-seed.js:44` is the only other writer of `db.data.config` and it is not reachable
  from a request. So `removeIds(db, name, …)` can never be pointed at an arbitrary collection.
- **A teacher reaches none of it** — `proposal` and `approve` are 403 for `j.nowak`; `run` is admin-only,
  and even the principal gets 403 on `run`.

**Everything else**

- **`publicConfig` key-by-key.** All 55 keys of `config` were listed against what a pupil receives
  (`repro/s3-15-publicconfig.js`). Besides `video` (S3-02), three more deserve a look but are not
  findings on their own: `ipAllowlistNote` states in plain Polish that *„logowania administracyjne nie są
  ograniczone adresem"* and `ipAllowlistExample` shows three concrete addresses — withholding
  `ipAllowlist` while shipping a sentence about whether it is empty defeats the point; `payroll` (787 B)
  carries teachers' pensum, hourly rates and the legal basis of overtime pay to every pupil and parent;
  and `require2FAForGradeEditors` / `sessionTimeoutMin` / `logRetentionYears` describe the security
  posture. Worth trimming in the same patch as S3-02.
- **The setup gate's other exceptions are correct**: `/api/setup/*`, `/api/auth/policy` and `/api/health`
  expose no school data before configuration.
- **The store is a Proxy and the round-3 routes respect it** — no `db.data.<col>` rebuild outside
  `removeIds`/`sweepOperational`, where a whole-collection replacement is the documented intent.

## Themes for the fix round

1. **A public route is not a small thing in a single-node process.** S3-01 and S3-03 are the same
   mistake seen twice: `{ public: true }` was added for a document that the law says must be published,
   and it brought with it the full fact-gathering machinery behind that document. Any future public route
   should be answered from a precomputed, cached, deliberately narrow object.
2. **Free text is doing the work of a control.** The registrar's `legalBasis`, the administrator's
   `archiveConsentReference`, the `reason` on `privacy/forget`, the `reason` on `adult-access` — each is
   a string nobody validates and nobody cross-checks, standing in for a court order, an Archiwum
   Państwowe decision or a data subject's signature. Four of the medium findings (S3-10, S3-11, S3-14,
   S3-17) are variations on it.
3. **The guarantees are enforced on one path and not on its neighbour.** Grades are gated and messages
   are not (S3-04); culling is ceremonious and erasure is not (S3-06); the audit log is immutable through
   every verb and erasable through one helper (S3-05). The fix in each case is to move the check into
   `server/lib/domain.js`, which is where the codebase already keeps its one-gate helpers and where it
   has worked well.
